Using mterm

How to install mterm, open a session, detach and reattach, work with several windows, save what is on the screen and get by when something goes wrong. At the end you will find the complete reference of every command and every key.

Version 1.0 System Linux (x86-64 and 64-bit ARM) Dependencies none

Contents

Press / to search. The index at the end lists commands, keys, files and topics.

Introduction

What mterm is, what it is for and why it exists, given that screen already does.

What it is

mterm keeps the programs you launch in the terminal alive even when you close the terminal. You open a session, work inside it as in an ordinary terminal, then detach from it: the window closes but the programs keep running. Later, even from another window or from another computer connected through ssh, you reattach and find everything as it was, including what was written on the screen.

It is especially useful in three cases:

  • long jobs: a build, a download, an installation that you do not want to interrupt by closing the window;
  • dropped connections: if you work over ssh from the tablet and the network drops, the programs on the remote computer do not die; you reconnect and carry on;
  • modern full-screen programs, such as Claude Code, which look wrong inside screen and look exactly the same inside mterm as outside it.

Why screen is not enough

screen (and to some extent tmux) does not just pass along what the program writes: it reads it, builds its own internal copy of the screen and then rewrites it its own way to your terminal. Things get lost along the way: 24-bit colours become approximations, some modern sequences are dropped or altered, and the newest full-screen programs look messy or wrong.

mterm does the opposite: it interprets nothing. What the program writes reaches your terminal byte for byte, unchanged. That is why a program inside mterm behaves as if mterm were not there. The only thing mterm adds of its own is the status bar on the last line.

What it does not do

  • It does not split the screen into side-by-side panes like tmux: one window at a time, full screen.
  • It has no scroll-back mode inside the session: to reread past output use your terminal's scrolling, or save it to a file with Ctrl+a s.
  • It does not survive shutting down the computer: the session lives as long as the computer stays on.
  • One terminal at a time per session: if you attach from a second terminal, the first one is detached.

How it works, in brief

flowchart LR
  T["Your terminal"] <-->|"bytes untouched"| C["mterm<br/>(the part you see)"]
  C <-->|"local connection"| D["mterm in the background<br/>(keeps the session alive)"]
  D <--> S1["window 0<br/>shell or program"]
  D <--> S2["window 1<br/>shell"]

When you open a session, mterm starts a second part of itself that stays in the background and keeps the programs running. The part you see in the terminal only acts as a pipe. Detaching closes the pipe; the background part stays. Reattaching opens a new pipe to the same background part.

Installation

mterm is a single executable file: there are no libraries or other programs to install.

The ready-made program, with git clone

The repository already contains the compiled program, the file mterm (Linux x86-64: PC and tablet). Just clone it:

$ git clone https://github.com/nic-fio/MTERM.git
$ cd MTERM
$ ./mterm --help

Using it from any folder

To simply type mterm from any folder, copy it into ~/.local/bin (the reply means: installed in, followed by the path):

$ make install
installato in /home/nicfio/.local/bin/mterm

If you do not have make, you get the same result with ./build.sh install (which however recompiles and therefore needs Go) or by hand:

$ mkdir -p ~/.local/bin && cp mterm ~/.local/bin/

On Debian and Ubuntu the folder ~/.local/bin is already among those where the system looks for programs (if it is not found, log out of the computer session and log back in). The rest of the manual writes mterm: if you have not installed it, use ./mterm from the repository folder.

Just the program, from the releases

From the releases page download mterm-linux-amd64 (PC and x86-64 tablet) or mterm-linux-arm64 (Raspberry Pi and other 64-bit ARM), then:

$ mv ~/Scaricati/mterm-linux-amd64 ~/.local/bin/mterm
$ chmod +x ~/.local/bin/mterm
$ mterm --help

From the source code

You only need this if you want to modify mterm. On Debian or Ubuntu, the script tools/setup-dev.sh checks what is missing and installs it:

$ git clone https://github.com/nic-fio/MTERM.git
$ cd MTERM
$ tools/setup-dev.sh --install
$ make
$ make test

make rebuilds ./mterm from the code; make test runs all the automatic checks. The details are in the Technical Manual.

Getting started

Opening a session, leaving it to work on its own, finding it again, closing it.

Opening your first session

$ mterm

The screen clears and the usual shell appears, with a green bar on the last line in addition. You are inside the default session, which is called Default. From here you work normally: everything you launch runs inside the session.

The status bar

The bar at the bottom always tells you where you are:

 ⬢ Default  0  1                                        nicfio@tablet  22:14:05
  • ⬢ Default: the name of the session;
  • 0 1: the window numbers; the one you are in is highlighted (inverted colours);
  • on the right user@computer and the time, updated every second.

For a few seconds, in place of the user and time, the bar may show a message: for example the confirmation of a save. If the terminal is very short (fewer than 3 lines) the bar is not shown.

Detaching

Press Ctrl+a, release the keys, then press d. You are back at your previous terminal and this appears (detached):

[staccato]

The programs inside the session keep running. You can now even close the terminal window, or log out of ssh.

Even if you just close it

You do not have to detach with Ctrl+a d: if you close the terminal window, or if the connection drops, the session stays alive all the same. The command is there to free the terminal without closing it.

Reattaching

$ mterm

The same command as before: since the session Default already exists, mterm reattaches to it instead of creating a new one. The screen is back as it was when you detached, and whatever the programs wrote in the meantime is there.

Closing the session

A session ends when its last window closes. The simplest way is to exit the shell (the last line means session ended):

$ exit
[sessione terminata]

From outside, without going in, you close it with mterm kill Default (see Ending a session).

Sessions

You can have several sessions at the same time, each with its own name: for example one for work and one for a download.

Creating a named session

$ mterm new lavoro

Creates the session lavoro and enters it. n is the short form: mterm n lavoro. If a session with that name already exists, mterm leaves it alone and says so (the session «lavoro» already exists):

$ mterm new lavoro
mterm: la sessione «lavoro» esiste già

Without a name (mterm new) the session gets a number: 0, then 1 and so on, choosing the smallest free one.

Valid names

The name can contain letters, digits and symbols, but no spaces and no slash /. For compound words use a hyphen: mterm new backup-foto. With a space the name is refused (invalid session name):

$ mterm new "backup foto"
mterm: nome di sessione non valido: «backup foto»

The shortcut: mterm NAME

Typing just the name does the right thing by itself: if the session exists it reattaches to it, otherwise it creates it.

$ mterm lavoro

It is the command you will use most often. mterm on its own is the same thing with the name Default.

Names that match a command

A session named like an mterm command (ls, new, n, attach, a, kill, k, list, help) cannot be reached with the shortcut, because mterm runs the command. Avoid those names.

Starting a program directly

After -- you can name the program to start instead of the shell:

$ mterm new ai -- claude
$ mterm n -- htop

The session contains only that program: when the program ends, the session ends with it. If you would rather have a shell remain after the program ends, create the session normally and launch the program from inside it.

Seeing which sessions are active

$ mterm ls
sessioni attive (2):
  Default
  lavoro

The first line (active sessions) gives how many there are. If there are none, it says nessuna sessione attiva (no active sessions). mterm ls also tidies up: if a session died abruptly (for example because its process was killed) and left some traces behind, it clears them away.

Reattaching to a specific session

$ mterm attach lavoro
$ mterm a lavoro

Unlike the shortcut, attach never creates anything: if the session does not exist, it says so (no session «lavroo»: use «mterm ls»).

$ mterm a lavroo
mterm: nessuna sessione «lavroo» (usa «mterm ls»)

One session, one terminal at a time

If you attach to a session already open in another terminal (for example you had left it open on the PC and now you come in from the tablet), the old terminal is detached and shows (detached: session resumed elsewhere):

[staccato: sessione ripresa altrove]

Nothing is lost: the session has simply moved to the new terminal.

Ending a session

$ mterm kill lavoro
sessione «lavoro» terminata

The reply means session «lavoro» ended. k is the short form. All the programs in the session are closed immediately, without asking for confirmation: any unsaved work inside them is lost.

Windows

A session can contain several shells, called windows, like the tabs of a browser. You see one at a time; the others keep working in the background.

The Ctrl+a key

All commands inside a session are given in two steps: first Ctrl+a (hold down Ctrl, press a, release both), then a second key. For example Ctrl+a c means: Ctrl+a, then c.

If after Ctrl+a you press a key that is not a command, mterm passes both keys to the program, as if it were not there.

Opening a new window

Ctrl+a c opens a new shell and takes you there. Its number appears in the bar. Windows are numbered starting from 0; a number is not reused after its window has been closed.

Switching between windows

KeysEffect
Ctrl+a n or Ctrl+a spaceNext window (after the last one, back to the first).
Ctrl+a pPrevious window.
Ctrl+a 0 … 9Straight to the window with that number (if it does not exist, nothing happens).

When you go back to a window you find it as it was: whatever it wrote while you were not looking is there.

The window list

Ctrl+a " (double quotes: on an Italian keyboard Shift+2) shows the list, with the name of each window's program and an arrow on the current one (the heading means Windows — press the number, Esc to cancel):

  Finestre  —  premi il numero, Esc per annullare

 ►  0  bash
    1  bash
    2  htop

Press the number of the window you want, or Esc (or q) to go back where you were. While the list is open, other keys are ignored.

Closing a window

Two ways: exit the shell with exit, or Ctrl+a k, which closes the current window and the program it contains without asking for confirmation. You are taken to another window. If it was the last one, the session ends.

Saving the contents of a window

To keep, or reread at leisure, what a program has written.

Ctrl+a s saves everything the current window has shown (up to roughly the last 5 MB) into two files, in the folder you launched mterm from:

FileContents
mterm-lavoro-w0-221405.txtClean text, to open with any editor or search with grep.
mterm-lavoro-w0-221405.rawThe original bytes, colours included: cat of this file in the terminal shows it again identically.

The name is made of: the session, w plus the window number, and the time of the save (hours-minutes-seconds). The bar confirms it for a few seconds (salvato means saved):

 ⬢ lavoro  0                         ✔ salvato: mterm-lavoro-w0-221405.{txt,raw} (1834/2410 B)

If the folder is not writable, the bar shows ✗ salvataggio fallito (save failed) and the reason instead.

The text of full-screen programs

For the output of a shell the .txt file is faithful. For programs that redraw the screen at different points (editors, htop, Claude Code) the .txt contains the pieces of text in the order in which they were written, not the final image of the screen: in that case the .raw file is the one that counts.

Practical use

The most common situations, step by step.

Working on another computer with ssh

  1. From the tablet you connect to the computer: ssh server.
  2. On the server you open the session: mterm lavoro. mterm must be installed on the server.
  3. You start the long job. If the network drops, or you close the tablet, it carries on on the server.
  4. When you come back: ssh server and mterm lavoro again.

Claude Code and other full-screen programs

$ mterm new ai -- claude

Claude Code, vim, htop, less work as they do outside mterm: colours, cursor and keys are not touched. When you reattach, the program's screen reappears immediately, even if the program is idle, waiting, at that moment.

If you reattach from a terminal of a different size, the program receives the new size immediately and usually redraws itself. Text already written by a shell, on the other hand, stays at the old width, as also happens in screen and tmux.

When the program needs Ctrl+a

Many programs use Ctrl+a for their own purposes: in the shell, for example, it moves the cursor to the start of the line. Inside mterm that key is reserved; to send it to the program press it twice: Ctrl+a Ctrl+a. For the start of the line in the shell you can also use the Home key (↖).

mterm inside mterm

If you open mterm inside an mterm session (this happens easily over ssh, with mterm both on the tablet and on the server), the Ctrl+a keys go to the outer one. To control the inner one press Ctrl+a twice and then the key: for example Ctrl+a Ctrl+a d detaches the inner session. Two status bars one above the other are the sign that you are in this situation.

Starting a session from a script

If you run mterm new NAME -- command from a script or from a program that has no terminal, the session is created and the command starts, but mterm cannot display it and exits with an error (incompatible terminal):

$ mterm new notte -- ./backup.sh </dev/null
mterm: terminale non compatibile: inappropriate ioctl for device

The session, however, is alive and working in the background: later you find it with mterm ls and enter it with mterm a notte. Bear in mind that the exit status is 1 all the same.

The built-in guide

mterm --help (or -h or help) opens a tabbed guide in the terminal: Info, Comandi (commands), Tasti (keys), Esempi (examples).

KeysEffect
← →, Tab, h l, 1…4Switch tab.
↑ ↓, j kScroll by one line.
PgUp PgDn, space bScroll by one page.
g GStart / end of the tab.
q, EscQuit.

If the terminal is too small (fewer than 44 columns or 10 lines) the guide is shown as a page of text to scroll through; if the output goes to a file or to another program (mterm --help > guida.txt) it is written as plain text, without colours.

Troubleshooting

mterm's messages and what to do about them. Errors always begin with mterm:.

Error messages

mterm: nessuna sessione «NOME» (usa «mterm ls») (no session «NAME»: use «mterm ls»)
You asked to reattach to a session that does not exist: wrong name, or it has already ended (its last window closed, or the computer was restarted). Check with mterm ls. To create it, use mterm NAME.
mterm: la sessione «NOME» esiste già (the session «NAME» already exists)
The command new does not create a duplicate. To enter it: mterm a NAME or simply mterm NAME.
mterm: nome di sessione non valido (invalid session name)
The name contains a space, a tab or /. See Valid names.
mterm: manca il nome della sessione (session name missing)
The commands attach and kill need the name: mterm a lavoro.
mterm: terminale non compatibile (incompatible terminal)
mterm was launched without a terminal (from a script, from a service, with redirected input). If it was a new, the session was created anyway: see Starting a session from a script.
mterm: avvio della sessione «NOME» fallito (starting session «NAME» failed)
The background part did not start within two seconds. The reason is written in the log file named in the message (see A session's log). Typical causes: the program after -- does not exist or is not executable.

Other situations

The session has disappeared
A session ends when its last window closes (even one exit too many) or when the computer restarts. If it is neither of these, look at its log.
Moving the mouse produces strange characters
A program turned on mouse handling and did not turn it off. mterm turns it off by itself when you switch windows and when you detach; if it happens outside mterm, the command reset puts the terminal right.
The bar has disappeared or is covered by text
This happens for a moment with programs that write to odd places on the screen; the bar redraws itself as soon as the output stops, and in any case every second. If the terminal is fewer than 3 lines high, there is no bar by design.
After coming back the screen is garbled
The terminal probably has a different size from when you detached. In full-screen programs just wait a moment or press a key; in the shell, Ctrl+l clears the screen.
I cannot reread past output
mterm has no scrolling of its own: use the terminal's (mouse wheel or Shift+PgUp), which however contains only what passed before your eyes. For the whole output of a window use Ctrl+a s and open the .txt file.
I cannot reach window 10 with the numbers
The number keys only go up to 9. For windows 10 and above use Ctrl+a n / p.
I want the guide without colours
Set the variable NO_COLOR: NO_COLOR=1 mterm --help.

A session's log

Every session keeps a small diary of what happens to it: startup, attaches and detaches, errors. It is in /run/user/N/mterm/NAME.log (where N is your user number, usually 1000):

$ cat /run/user/1000/mterm/lavoro.log
2026-09-24 10:57:36 demone avviato: sessione «lavoro», pid 484239
2026-09-24 10:57:36 client attaccato
2026-09-24 11:20:02 client staccato

The lines mean daemon started (with the session and its process number), client attached, client detached. The log remains even after the session ends, until you create another one with the same name (which starts it over from scratch) or restart the computer.

Recovery on a new device

If the tablet breaks down, all of mterm can be recovered from GitHub with one command.

What is saved and where

The repository github.com/nic-fio/MTERM contains everything: the ready-made program, the code, the tests, these manuals, the tools and the entire history of changes. mterm has no personal files or passwords, so there is nothing to recreate by hand.

Starting again from scratch

  1. Install git, if it is missing: sudo apt install git.
  2. Clone the repository: git clone https://github.com/nic-fio/MTERM.git
  3. Go in and try the program: cd MTERM && ./mterm --help
  4. Install it to use it anywhere: make install (or cp mterm ~/.local/bin/).
  5. Optional, to modify it: tools/setup-dev.sh --install and then make test.

A backup that does not depend on GitHub

tools/backup.sh puts the whole repository, with all its history, into a single file to keep on a USB stick or a disk:

$ tools/backup.sh /media/chiavetta
/media/chiavetta/mterm-2026-09-24.bundle: 2,4M, 4 commit, tag: v1.0.0

To start again from that file, without a network:

$ git clone /media/chiavetta/mterm-2026-09-24.bundle MTERM
$ cd MTERM && ./mterm --help

Command and key reference

Everything mterm accepts, in the same order as the built-in guide.

Commands

mterm new [name] [-- command …]
Creates a session and enters it. Short form: n. Without a name it uses the smallest free number. After --, the program to start instead of the shell ($SHELL). See Creating a session.
mterm attach NAME
Reattaches to the session. Short form: a. It never creates a session. If another terminal was attached, it is detached.
mterm ls
Lists the active sessions in alphabetical order and removes the traces of dead ones. Also mterm list.
mterm kill NAME
Ends the session and all its programs immediately. Short form: k.
mterm NAME
If the session exists it reattaches to it, otherwise it creates it. With no argument at all, mterm does the same with the session Default.
mterm --help
Opens the built-in guide. Also -h, -help and help. See The built-in guide.

Keys during a session

Ctrl-a d
Detaches the session: the terminal is free again, the programs keep running.
Ctrl-a c
New window with a new shell (always $SHELL, even if the session was started with another program).
Ctrl-a n / Ctrl-a space
Next window.
Ctrl-a p
Previous window.
Ctrl-a 0 … 9
Goes to the window with that number, if it exists.
Ctrl-a "
Window list: a number to choose one, Esc or q to cancel.
Ctrl-a k
Closes the current window without confirmation. If it is the last one, it ends the session.
Ctrl-a s
Saves the contents of the window to mterm-SESSION-wN-TIME.txt and .raw, in the folder you launched mterm from. See Saving the contents.
Ctrl-a Ctrl-a
Sends a Ctrl+a to the program in the window.

The letters also work in upper case, except n and p. Any other key after Ctrl+a reaches the program together with the Ctrl+a.

Files used

PathContents
$XDG_RUNTIME_DIR/mterm/NAME.sockThe session's point of contact (not a file to open). On Debian $XDG_RUNTIME_DIR is /run/user/1000.
$XDG_RUNTIME_DIR/mterm/NAME.logThe session's log.
/tmp/mterm-N/Used instead of the previous one if XDG_RUNTIME_DIR is not set (for example in some unusual kinds of connection).
mterm-SESSION-wN-TIME.txt, .rawCreated by Ctrl+a s in the current folder.

Everything lives in folders that the system empties at every restart: mterm leaves nothing lying around in your home folder.

Exit status

Glossary

Session
A named group of windows, which stays alive in the background even when no terminal is showing it.
Window
A shell (or a program) inside a session. You see one at a time.
Detach
Leaving the session without closing it: the programs carry on.
Reattach (attach)
Going back to seeing and using a session left in the background.
Shell
The program that shows the prompt and runs the commands you type, usually bash.
Full-screen program
A program that takes up the whole terminal window and redraws it, such as an editor or Claude Code.
24-bit colour
Millions of exact colours, instead of the reduced palette of older terminals.
Release
A published version of the program, with the ready-made file to download.
